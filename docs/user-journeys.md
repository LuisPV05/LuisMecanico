# Jornadas de usuario

Recorridos completos de uso una vez desarrollado el sistema.


## Jornada 1: Luis cierra una cita por teléfono sin colgar dos veces

1. Kips llama contando que el coche le hace un ruido raro al frenar.
2. Luis mete el síntoma en el sistema, que deduce que hace falta un elevador durante 1h30.
3. Kips pide que sea a las 10:00, así que Luis intenta registrar la cita a esa hora.
4. El sistema comprueba los tres elevadores y ve que a esa hora ya están todos ocupados.
5. Devuelve el primer hueco libre, las 11:30, y Luis se lo ofrece a Kips ahí mismo, sin colgar y tener que llamarle otra vez luego.


## Jornada 2: Luis encaja un imprevisto sin repasar toda la agenda

1. Un cliente se presenta sin cita pidiendo una reparación urgente.
2. Luis necesita saber, ya mismo, si el gato hidráulico está libre en la próxima hora.
3. Consulta ese recurso en concreto, sin tener que mirar toda la agenda del día.
4. El sistema le confirma que hay un hueco libre de una hora.
5. Luis acepta el trabajo sin descuadrar el resto de citas que ya tiene puestas.


## Jornada 3: Snoopy sufre un retraso que afecta a la siguiente cita, detectanado el efecto dominó de un retraso 

1. Snoopy lleva ya 45 minutos de retraso sobre lo que se había calculado para una reparación.
2. El sistema compara ese tiempo real con la duración estimada del recurso que está usando.
3. Se da cuenta de que la siguiente cita en ese mismo elevador se va a ver afectada.
4. Identifica qué cita se ve afectada y se lo muestra a recepción, que decide si llama al cliente.
5. Recepción llama al cliente antes de que este se presente en el taller.
